# 开放题式人格测评 · 行为叙述版

把选择题换成受测者自己写的场景。每一题给一个情境框定，你写下自己在类似情境下**会产生的行为与想法**；
模型读的是你的原话，按各套量表原有的维度框架给出倾向、置信度，以及一份能逐句追溯到原文的人物小传。

内置四个测试，共用同一套引擎（开放题 + 引文溯源 + 人物小传）：

| 测试 | 维度 | 题量 |
|---|---|---|
| 开放题版 MBTI | 能量朝向 / 信息摄取 / 决策方式 / 生活节奏 | 4 维 · 24 题 |
| 开放题版大五人格 | 神经质 / 尽责性 / 外向性 / 宜人性 / 开放性 | 5 维 · 30 题 |
| 开放题版职业画像 | 兴趣方向 / 优势偏好 / 协作方式 / 节奏偏好 | 4 维 · 24 题 |
| 开放题版关系与依恋模式 | 依恋倾向 / 冲突反应 / 需求表达 / 投入与边界 | 4 维 · 24 题 |

> 这是一份**倾向画像**，不是类型判定，也不是任何形式的诊断。
> 产出没有信效度检验，**不适用于招聘筛选、升学分流等高风险决策**。

## 两种运行方式

同一份代码，两种形态，判型规则完全一致（共用 `public/lib/` 下的同一份实现）。

### 一、本机运行（推荐用于自用）

```bash
git clone <本仓库>
cd mbti-open
npm start
```

打开 http://127.0.0.1:5173

- 服务端**只监听 127.0.0.1**，不对外暴露。
- 判型请求同样由浏览器直连 `api.minimaxi.com`——本机与线上行为完全一致，
  都需要访客自己填 API Key，密钥只存在浏览器里。
- 作答不落盘；草稿存在浏览器 localStorage 里。

### 二、静态部署（GitHub Pages）

仓库的 `public/` 目录就是站点根目录，由 GitHub Actions 发布。

- 页面是**纯静态**的，没有后端。
- **访客需要填自己的 MiniMax API Key**（本机与线上的行为完全一致）。
  Key 只存在访客的浏览器 localStorage 里，不经过任何服务器，**仓库和页面上都没有密钥**。
- 判型请求由浏览器直接发往 `api.minimaxi.com`（该端点支持 CORS）。

访问地址形如 `https://<你的用户名>.github.io/<仓库名>/`。

本仓库的线上地址：<https://tianayan.github.io/psytestopen/>

## 交互流程

1. **开始页**：先选**测什么**（四个测试入口），再选版本、填 API Key。
2. **逐维作答**：每组一屏一题，含写作指引与三项最小信息自检。
3. **提交即跳转**：一维填完点「提交并继续下一维」，**立刻进入下一维**，本维判型在后台并行计算，
   页面顶部状态条实时显示 `待答 / 作答中 / 计算中 / 完成 / 失败`。
4. **可以跳题**：任何一题写不出来，点「跳过这题」即可。跳过的题号会随请求一起提交，
   模型被明确告知「不得为其编造证据」，该题会被如实记进证据缺口；报告里还会写明
   「本维度实际作答 N 题，跳过 M 题」。某一维至少要写一题。
5. **失败可重试**：某维判型失败时给出原因与「重试评判」按钮，作答不会丢。
6. **一次性汇总**：所有维度齐备后自动合成报告——类型字母、整体置信度、各维读数表、人物小传、
   证据边界、每个维度的完整判型依据（支撑证据 / 反向证据 / 易误读核对 / 证据缺口）、引证表。
7. **重新合成**：报告页可「重新合成报告」，复用已有作答不必重答。
8. **打印 / 存为 PDF**：打印对话框的默认文件名取自页面标题，而标题随所测测试变化——
   四套测试分别存成「开放题版 MBTI · 倾向画像」「开放题版大五人格 · 倾向画像」
   「开放题版职业画像 · 倾向画像」「开放题版关系与依恋模式 · 倾向画像」，不会互相覆盖。

### 两个版本

| | 完整版 | 快速版 |
|---|---|---|
| 每个维度 | 6 题 | 4 题（只取 `core` 层） |
| 预计用时 | 约 15–20 分钟 | 约 10–13 分钟 |
| 证据厚度 | 每维多两个行为侧面，反向证据更容易浮出来 | 少两个侧面，置信度通常更低 |

题库每题带 `tier` 标记：`core` 进两个版本，`extended` 只进完整版。
分层的依据是**误读风险**——`extended` 的题锚点最容易读偏（"挺累"不等于 I、"自责"不等于 F、
"被问出来的未来"不等于 N 等），完整版有更多题可以交叉印证它们，快速版则直接不用它们。
换版本会让已写的作答失效（题集变了），所以已有进度时不再提供切换入口。

## 设计要点

- **套件化**：每个测试 = 一套维度定义 + 一套题库 + 一套维度透镜，放在 `public/suites/<id>.json`。
  引擎（`public/lib/`）对所有测试是同一份代码，新增测试只需加一个套件文件。
- **维度锁定靠结构，不靠提示词**：一次判型请求只接收一个维度的题，输入里不存在其他维度的作答，
  模型无从跨维度推断；提示层再叠加该维专属的维度透镜、每题锚点与误读防护。
- **引文可溯源靠程序校验**：模型给出的每条引文必须在作答原文中**逐字命中**（规范化后子串匹配，
  最短 4 字）；命中失败即丢弃该条并下调该维置信度。引证表里的每一条都能回查。
- **类型字母由逐维倾向拼出**，不采信模型单写的 `type` 字符串。取值优先级：
  单维判型结论 → 汇总阶段的逐维结论 → 模型写的字母（须属于本维度两极）。
  这保证了报告顶部的大字母与「各维读数」表在结构上不可能自相矛盾。
- **字母口径也随套件走**：字母数必须等于维度数，每一位都要落在该维度的两个极值里——
  MBTI 是 E/I、S/N…，大五人格是 L/H、I/O…，职业画像是 P/R、D/B…，
  关系套件是 N/S、W/P…。任何写死单一量表字母的地方，都会让其余三套测试永远读不出倾向。
- **小传每段必须带可溯源引文**，且至少有一段要写出证据薄弱、彼此矛盾或随情境变化的地方；
  不过关则重生成一次，仍不过关就降级为只拼原话的保守版。
- **服务端与浏览器共用一份判型实现**（`public/lib/`），因此本地跑出来的结果与线上跑出来的结果口径一致。

## 目录结构

```
server.mjs          本机服务端（只监听 127.0.0.1；判型走浏览器直连）
lib/config.mjs      仅服务端：解析凭证与端点配置
public/             ← GitHub Pages 的站点根目录
  index.html
  app.js            前端状态机与渲染（一律浏览器直连）
  styles.css
  suites/           ← 每个测试一套：维度 + 透镜 + 题库
    index.json      入口目录（id / 名称 / 一句话说明 / 题量）
    mbti.json       4 维 · 24 题
    bigfive.json    5 维 · 30 题
    career.json     4 维 · 24 题
    relationship.json 4 维 · 24 题
  lib/
    prompts.js      提示词与输出格式（透镜随套件走，不写死任何量表）
    validate.js     引文校验、字母派生、降级
    llm.js          API 调用层（协议适配、超时、重试、脱敏）
    pipeline.js     判型流程：服务端与浏览器共用的唯一实现
test/               离线测试（不依赖真实 API）
  contract.test.mjs   契约：引文校验、类型派生、服务端接口
  pipeline.test.mjs   流程：提示词、跳题、证据缺口
  views.test.mjs      视图：前端各页渲染与转义
  suites.test.mjs     套件：文件契约 + 浏览器调用链（含"漏传透镜"回归）
```

## 开发

```bash
npm test
```

72 条断言，覆盖：套件文件契约（透镜齐全、题目挂对维度、题号唯一）、
题目库完整性与分层、跳题与证据缺口、引文校验与丢弃规则、字母派生与更正、
小传降级、服务端接口契约、前端视图渲染与转义，
以及**浏览器调用链**——套件化重构时曾漏传 `dimensionMeta` / `dimensions`，
四个维度全部报"维度缺少透镜定义"，而纯函数测试照样全绿；
现在把调用参数组装抽成纯函数后直接断言，这类漏参会被测试拦住。

## 题目来源与致谢

- 题目以**标准 MBTI 的维度构念与题位分布**为骨架，逐题重写为原创开放情境题，不复制任何原题表述。
- 维度透镜的「易误读清单」与「证据门槛」写法参考了开源项目
  [OriSelf](https://github.com/Deep-Thinks/oriself-next)（Apache-2.0）。
- MBTI 是 Myers-Briggs Type Indicator 的缩写，属受注册商标保护的量表；
  本项目是**原创的开放题改编与研究性工具**，与 Myers & Briggs Foundation 无任何关联。

## 隐私

- 作答只发往判型 API 端点（本机部署时是本机服务与你的账号；静态部署时是你自己填 Key 的那个端点）。
- 任何情况下作答都不落在服务器上；草稿保存在访客自己的浏览器里。
- 仓库里不存在任何凭据，`.env.local` 已被 `.gitignore` 排除。
