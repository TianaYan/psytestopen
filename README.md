# 开放题版 MBTI · 行为叙述测评

把选择题换成受测者自己写的场景。每一题给一个情境框定，你写下自己在类似情境下**会产生的行为与想法**；
模型读的是你的原话，按 MBTI 原有的维度框架给出倾向、置信度，以及一份能逐句追溯到原文的人物小传。

> 这是一份**倾向画像**，不是类型判定，也不是任何形式的诊断。
> 产出没有信效度检验，**不适用于招聘筛选、升学分流等高风险决策**。

## 两种运行方式

同一份代码，两种部署形态，判型规则完全一致（共用 `public/lib/` 下的同一份实现）。

### 一、本机运行（推荐用于自用）

```bash
git clone <本仓库>
cd mbti-open
npm start
```

打开 http://127.0.0.1:5173

- 服务端**只监听 127.0.0.1**，不对外暴露。
- 密钥由服务端从本机配置读取（依次尝试 `MBTI_API_KEY` 环境变量 → `.env.local` →
  `%USERPROFILE%\.minimax\agents\coder\config.yaml`），**浏览器拿不到密钥**。
- 作答不落盘；草稿存在浏览器 localStorage 里。

### 二、静态部署（GitHub Pages）

仓库的 `public/` 目录就是站点根目录，由 GitHub Actions 发布。

- 页面是**纯静态**的，没有后端。
- 访客需要填**自己的** MiniMax API Key。Key 只存在访客的浏览器 localStorage 里，
  不经过任何服务器，**仓库和页面上都没有密钥**。
- 判型请求由浏览器直接发往 `api.minimaxi.com`（该端点支持 CORS）。

访问地址形如 `https://<你的用户名>.github.io/<仓库名>/`。

本仓库的线上地址：<https://tianayan.github.io/psytestopen/>

本地想验证静态链路时，加 `?mode=direct` 强制走直连模式（`?mode=local` 强制走本机服务）：

```
http://127.0.0.1:5173/?mode=direct
```

### 三、公网部署（访客免登录直接用）

GitHub Pages 只能托管静态文件，放不下服务端密钥，所以"访客不用登录、也不用自己填 Key"
这种体验需要把 `server.mjs` 一并部署出去。好在前端会自动判断走哪条链路——
**同一份代码，两种接法，访客不需要知道区别**：

| 部署形态 | 前端如何决策 | 访客体验 | 你的成本 |
|---|---|---|---|
| 本机 `npm start` | 探到同源 `/api/health` → 走后端 | 打开即用，不填 Key | 0（用你自己的账号额度） |
| 公网部署本服务（Docker/Fly 等） | 同上 | 打开即用，不填 Key | 你承担全部推理费用 |
| 纯静态（GitHub Pages） | 探不到后端 → 浏览器直连 | 要自己填一个 Key | 0 |

判定逻辑在 `public/app.js` 的 `decideTransport()`，可用 `?mode=direct` / `?mode=server` 强制。

#### 服务端配置项

| 变量 | 默认 | 说明 |
|---|---|---|
| `HOST` | `127.0.0.1` | 监听地址。公网部署设为 `0.0.0.0` |
| `PORT` | `5173` | 端口 |
| `MBTI_CORS_ORIGINS` | （仅本机） | 允许的前端来源，逗号分隔；`*` 全放行。前后端同源时不必设 |
| `MBTI_RATE_LIMIT` | `30` | 每 IP 每分钟接口调用上限，超了返回 429 |
| `MBTI_RATE_WINDOW_MS` | `60000` | 限流窗口 |
| `MBTI_TRUST_PROXY` | （关） | 置 `1` 时才采信 `X-Forwarded-For`（反代后必开，否则限流会误伤） |
| `MBTI_API_KEY` | 本机配置 | 站点用的密钥，**只放服务端** |

#### 部署到 Fly.io

```bash
fly launch --no-deploy --copy-config deploy/fly.toml
fly secrets set MBTI_API_KEY=sk-...      # 不要提交进 git
fly deploy --config deploy/fly.toml
```

`Dockerfile` 已备好（零 npm 依赖，不需要 `npm install`），前端与 API 同源部署，
浏览器只访问一个域名，因此不需要配 `MBTI_CORS_ORIGINS`。

> 提醒：公网部署意味着**每个访客都在消耗你的额度**。上线前务必确认
> `MBTI_RATE_LIMIT` 与 `MBTI_CORS_ORIGINS` 已经设好，并清楚这是一个开放给公网的入口。

## 交互流程

1. **开始页**：说明玩法与边界；选择版本（见下）；静态部署版在此填写 API Key。
2. **逐维作答**（E/I → S/N → T/F → J/P）：每组一屏一题，含写作指引与三项最小信息自检。
3. **提交即跳转**：一维填完点「提交并继续下一维」，**立刻进入下一维**，本维判型在后台并行计算，
   页面顶部状态条实时显示 `待答 / 作答中 / 计算中 / 完成 / 失败`。
4. **可以跳题**：任何一题写不出来，点「跳过这题」即可。跳过的题号会随请求一起提交，
   模型被明确告知「不得为其编造证据」，该题会被如实记进证据缺口；报告里还会写明
   「本维度实际作答 N 题，跳过 M 题」。某一维至少要写一题。
5. **失败可重试**：某维判型失败时给出原因与「重试评判」按钮，作答不会丢。
6. **一次性汇总**：四维齐备后自动合成报告——类型字母、整体置信度、四维读数表、人物小传、
   证据边界、四个维度的完整判型依据（支撑证据 / 反向证据 / 易误读核对 / 证据缺口）、引证表。
7. **重新合成**：报告页可「重新合成报告」，复用已有作答不必重答。

### 两个版本

| | 完整版 | 快速版 |
|---|---|---|
| 每个维度 | 6 题 | 4 题（只取 `core` 层） |
| 总题量 | 24 题 | 16 题 |
| 预计用时 | 约 15–20 分钟 | 约 10–13 分钟 |
| 证据厚度 | 每维多两个行为侧面，反向证据更容易浮出来 | 少两个侧面，置信度通常更低 |

题库每题带 `tier` 标记：`core` 进两个版本，`extended` 只进完整版。
分层的依据是**误读风险**——`extended` 那 8 题的锚点最容易读偏（"挺累"不等于 I、"自责"不等于 F、
"被问出来的未来"不等于 N 等），完整版有更多题可以交叉印证它们，快速版则直接不用它们。
换版本会让已写的作答失效（题集变了），所以已有进度时不再提供切换入口。

## 设计要点

- **维度锁定靠结构，不靠提示词**：一次判型请求只接收一个维度的 6 题，输入里不存在其他维度的作答，
  模型无从跨维度推断；提示层再叠加该维专属的维度透镜、每题锚点与误读防护。
- **引文可溯源靠程序校验**：模型给出的每条引文必须在作答原文中**逐字命中**（规范化后子串匹配，
  最短 4 字）；命中失败即丢弃该条并下调该维置信度。引证表里的每一条都能回查。
- **类型字母由逐维倾向拼出**，不采信模型单写的 `type` 字符串。取值优先级：
  单维判型结论 → 汇总阶段的逐维结论 → 模型写的字母（须属于本维度两极）。
  这保证了报告顶部的大字母与「四维读数」表在结构上不可能自相矛盾。
- **小传每段必须带可溯源引文**，且至少有一段要写出证据薄弱、彼此矛盾或随情境变化的地方；
  不过关则重生成一次，仍不过关就降级为只拼原话的保守版。
- **服务端与浏览器共用一份判型实现**（`public/lib/`），因此本地跑出来的结果与线上跑出来的结果口径一致。

## 目录结构

```
server.mjs          本机服务端（只监听 127.0.0.1）
lib/config.mjs      仅服务端：解析凭证与端点配置
public/             ← GitHub Pages 的站点根目录
  index.html
  app.js            前端状态机与渲染（双模式：local / direct）
  styles.css
  items.json        24 道题：4 维 × 6 题
  lib/
    prompts.js      提示词与四套维度透镜
    validate.js     引文校验、类型派生、降级
    llm.js          API 调用层（协议适配、超时、重试、脱敏）
    pipeline.js     判型流程：服务端与浏览器共用的唯一实现
test/               离线测试（不依赖真实 API）
```

## 题目来源与致谢

- 题目以**标准 MBTI 的维度构念与题位分布**为骨架，逐题重写为原创开放情境题，不复制任何原题表述。
- 维度透镜的「易误读清单」与「证据门槛」写法参考了开源项目

- MBTI 是 Myers-Briggs Type Indicator 的缩写，属受注册商标保护的量表；
  本项目是**原创的开放题改编与研究性工具**，与 Myers & Briggs Foundation 无任何关联。

## 隐私

- 作答只发往判型 API 端点（本机部署时是本机服务与你的账号；静态部署时是你自己填 Key 的那个端点）。
- 任何情况下作答都不落在服务器上；草稿保存在访客自己的浏览器里。
- 仓库里不存在任何凭据，`.env.local` 已被 `.gitignore` 排除。
